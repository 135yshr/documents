## はじめに

以前、MarkdownをPDFに変換するCLIツール **md2pdf** を作りました。

[md2pdf repository](https://github.com/135yshr/md2pdf)

Markdownから、GitHub風のスタイル、Mermaid、日本語、テーブル、コードブロックなどを含んだPDFを生成できます。

```sh
md2pdf report.md
```

これはこれで便利なのですが、実際に仕事で使おうとすると一つ問題が出てきました。

**Markdownは同じままで、PDFの見た目だけ変えたい。**

顧客へ提出するレポート、セキュリティ診断報告書、技術提案書、社内標準フォーマットなどでは、GitHub風の見た目だけでなく、自社や顧客のブランドに合わせたデザインが必要になることがあります。

そこでmd2pdfに **Custom CSS機能** を追加しました。

```sh
md2pdf -css brand.css report.md
```

これでMarkdown本文を変更せず、PDFのデザインだけを変更できます。

## Markdownにデザインを持ち込まない

今回一番やりたかったのは、内容と見た目の分離です。

Markdown側にはできるだけ「意味」だけを書きます。

```markdown
# Security Assessment Report

## Executive Summary

今回の調査では3件のHighリスク項目を確認しました。

## Findings

| Severity | Finding |
| --- | --- |
| High | SQL Injection |
| Medium | Missing CSP |
```

見た目のためだけにHTMLをMarkdownへ埋め込み始めると、Markdown自体が特定の出力形式に依存してしまいます。

理想は次の分離です。

```text
Content
   ↓
Markdown

Design
   ↓
CSS
```

そこで、デザインは外部CSSとして渡す形にしました。

## 基本的な使い方

例えば次のCSSを用意します。

```css
body {
  font-family: "Noto Sans CJK JP", sans-serif;
  font-size: 11pt;
  line-height: 1.7;
}

h1 {
  font-size: 28pt;
  border-bottom: 4px solid #333;
  padding-bottom: 8px;
}

h2 {
  margin-top: 2em;
  border-left: 5px solid #333;
  padding-left: 12px;
}

table {
  width: 100%;
}
```

あとは次のように実行します。

```sh
md2pdf -css report.css report.md
```

Markdown本文は一切変更せず、PDFだけデザインを変更できます。

## CSSは組み込みスタイルの後に適用する

md2pdfには元々GitHub風のCSSがあります。Custom CSSは、その組み込みCSSの後に適用します。

```text
built-in CSS
    ↓
custom CSS
```

ただし、CSSのCascadeでは単純に「後に書かれたものが必ず勝つ」わけではありません。`!important`、Cascade Origin、詳細度などが先に評価され、**それらが同じ条件のときにソース順が決め手になります**。

例えば、先に読み込まれたCSSに、

```css
.report h1 {
  color: blue;
}
```

があり、後から読み込んだCSSに、

```css
h1 {
  color: red;
}
```

があっても、前者の方が詳細度が高いため青が優先されます。

そのため、複数CSSを重ねる場合は、上書き対象のセレクタの詳細度を揃えるか、必要に応じてCSS Cascade Layersなどで優先関係を明示するのが安全です。

単純なスタイル調整であれば、組み込みCSSをすべてコピーする必要はなく、変更したい部分だけ上書きできます。

## CSSを複数指定できるようにした

`-css` は複数回指定できます。

```sh
md2pdf \
  -css company.css \
  -css customer.css \
  report.md
```

読み込み順は次の通りです。

```text
Built-in CSS
      ↓
company.css
      ↓
customer.css
```

同じ重要度・詳細度のルール同士であれば、後から指定したCSSが優先されます。

これは実際の業務を考えると便利です。例えば、

```text
styles/
├── company.css
├── security-report.css
├── customer-a.css
└── customer-b.css
```

としておけば、

```sh
md2pdf \
  -css styles/company.css \
  -css styles/security-report.css \
  -css styles/customer-a.css \
  report.md
```

のように、会社共通、文書種類、顧客固有というレイヤーでスタイルを管理できます。

## HTML出力も追加した

Custom CSSを実装してすぐ気付いた問題があります。

PDFでCSSを調整するのは面倒です。

```text
CSS変更
 ↓
PDF生成
 ↓
PDFを開く
 ↓
確認
 ↓
CSS変更
```

そこで同時にHTML出力も追加しました。

```sh
md2pdf -format html document.md
```

Custom CSSとも組み合わせられます。

```sh
md2pdf \
  -format html \
  -css report.css \
  report.md
```

生成されるHTMLにはCSSがインラインで埋め込まれます。そのため、**`report.css` を編集してブラウザをリロードするだけでは変更は反映されません**。

CSSを変更したら、HTMLを再生成します。

```sh
md2pdf \
  -format html \
  -css report.css \
  report.md
```

そのあとブラウザをリロードします。

```text
CSS変更
 ↓
md2pdfでHTMLを再生成
 ↓
Browser Reload
 ↓
確認
```

PDFを毎回生成するよりも軽く確認でき、完成したら、

```sh
md2pdf -css report.css report.md
```

でPDFを作ります。

## HTMLとPDFで同じCSSを使う

この仕組みで重要なのは、HTMLとPDFで同じCSSを使うことです。

md2pdfのPDF生成は概ね次のパイプラインです。

```text
Markdown
   ↓
goldmark
   ↓
HTML
   ↓
CSS
   ↓
Chromium
   ↓
PDF
```

HTML出力は、この途中で止めるだけです。

```text
Markdown
   ↓
goldmark
   ↓
HTML + CSS
   ↓
report.html
```

そのためHTMLで確認したスタイルを、そのままPDF生成にも利用できます。

## Chromiumを直接操作する

md2pdfの初期バージョンではPDF生成にPython + Playwrightを使っていました。

現在はGoからChromium DevTools Protocolを直接操作しています。

```text
Markdown
 ↓
HTML
 ↓
CSS
 ↓
Chromium
 ↓
Page.printToPDF
 ↓
PDF
```

つまりPDF生成と言っても、実際には「Webページを作ってChromiumで印刷する」という考え方です。そのためCSSとの相性が非常に良いです。

## 例えば社内ブランド用PDFを作る

例えば会社の資料用に次のようなCSSを作っておきます。

```css
:root {
  --primary: #1f4e79;
  --border: #d0d7de;
}

body {
  font-family: "Noto Sans CJK JP", sans-serif;
}

h1,
h2 {
  color: var(--primary);
}

h1 {
  border-bottom: 3px solid var(--primary);
}

blockquote {
  border-left: 4px solid var(--primary);
  background: #f6f8fa;
  padding: 12px 16px;
}
```

これを、

```sh
md2pdf -css company.css proposal.md
```

のように利用できます。

顧客固有の差分を別CSSに切り出せば、同じMarkdownから複数ブランドの成果物を生成できます。

## MarkdownとCSSをGitで管理する

この形にすると、MarkdownだけでなくデザインもGitで管理できます。

```text
docs/
├── report.md
└── styles/
    ├── base.css
    ├── security.css
    └── customer-a.css
```

デザイン変更も普通のコードと同じようにdiffでレビューできます。

```diff
 h1 {
-  font-size: 24px;
+  font-size: 28px;
 }
```

バイナリのWordテンプレートやPDFテンプレートとは違い、デザイン変更自体をGitでレビューできるのはDocs as Codeとの相性が良い点です。

## CIでPDFを生成する

MarkdownとCSSをGit管理しているので、CIにも載せやすくなります。

```yaml
- name: Build report
  run: |
    md2pdf \
      -css styles/company.css \
      -css styles/report.css \
      report.md
```

```text
Markdown
   +
CSS
   +
Git
   ↓
CI
   ↓
PDF Artifact
```

つまり、文書作成もソフトウェアのビルドに少し近づきます。

## AI時代のドキュメント生成とも相性がいい

最近はAI Coding AgentやLLMに、設計書、調査報告、ADR、セキュリティレポート、実装計画などを書かせる機会が増えています。

AIにWord文書やPDFそのものを作らせることもできますが、個人的には、

```text
AI
 ↓
Markdown
 ↓
Review
 ↓
Renderer
 ↓
PDF
```

という構成の方が扱いやすいと感じています。

MarkdownならGit diffでレビューでき、出力の見た目はCSS側で制御できます。

```text
AI = Content
CSS = Presentation
Git = Review / History
md2pdf = Renderer
```

AIには内容を書かせて、デザインは決定論的なCSSに任せるという役割分担です。

## `</style>` を含むCSSは拒否する

Custom CSSを追加すると、一つ注意点があります。

md2pdfではCSSをHTML内の `<style>` にインライン展開しています。そのためCSSファイルに、

```html
</style>
```

が含まれていると、style要素を閉じてHTMLを挿入できてしまいます。

そこで現在は `</style` を含むCSSをエラーにしています。CSSとして通常必要になる文字列ではないため、曖昧にエスケープするよりも明示的に拒否する方針にしました。

## DOCXとConsoleは別の仕組み

Custom CSSはPDFとHTMLに適用します。

DOCXはPandocのreference document、ConsoleはGlamourのstyleを使っているため、それぞれ別の仕組みです。

```text
                  ┌─ PDF ─── CSS
                  │
Markdown ─────────┼─ HTML ── CSS
                  │
                  ├─ DOCX ── reference document
                  │
                  └─ Console ─ Glamour Style
```

出力形式に無理やり共通のスタイル機構を押し込まず、それぞれに適した仕組みを使っています。

## md2pdfが目指しているもの

最初にmd2pdfを作ったときは、

```text
Markdown → PDF
```

だけを考えていました。

現在は、

```text
                   ┌─ Terminal
                   │
Markdown ──────────┼─ HTML
                   │
                   ├─ PDF
                   │
                   └─ DOCX
```

となり、さらに内容とPresentationも分離できるようになりました。

最近はmd2pdfを単なるPDFコンバーターというより、**Markdownを原本として、用途に応じた成果物を作るCLI** として考えるようになっています。

## まとめ

md2pdfにCustom CSS機能を追加しました。

```sh
md2pdf -css report.css report.md
```

CSSは複数指定できます。

```sh
md2pdf \
  -css company.css \
  -css customer.css \
  report.md
```

HTMLでプレビューする場合は、CSSを変更するたびにHTMLを再生成します。

```sh
md2pdf \
  -format html \
  -css report.css \
  report.md
```

今回の機能によって、

```text
Markdown = 内容
CSS      = デザイン
Git      = バージョン管理
md2pdf   = レンダリング
```

という構成が取れるようになりました。

特にAIでMarkdownを生成する機会が増えている今、**内容の生成と成果物のデザインを分離する**ことには以前より意味があると思っています。

Markdownでドキュメントを管理しつつ、顧客向け・社内向けのPDFも同じソースから作りたい方は、よければ試してみてください。

[md2pdf repository](https://github.com/135yshr/md2pdf)

```sh
brew install 135yshr/tap/md2pdf
```
