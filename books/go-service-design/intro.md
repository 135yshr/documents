## この本について

「クリーンアーキテクチャというアーキテクチャは存在しない」と言われることがあります。私もこの言葉に賛成です。同心円の図をそのまま写しても、動くサービスは出てきません。あの図が教えてくれるのは依存の向きという原則だけです。レイヤーをいくつ作るか、interface をどこに置くか、DB への依存をどこまで剥がすか。そこは全部自分で判断するしかありません。

この本は、Go でサービスを設計・運用する中でこれまでに疑問に思い調べてきた、「自分で判断するしかない部分」の判断基準をまとめたものです。元になっているのは Zenn に公開してきた設計に関する記事群です。ただし単に束ねたのではなく、原則から実践へ一本の流れになるよう構成を組み直しました。記事間で揺れていた用語の統一と、誤りの修正も行っています。

ゴールは1つです。読み終えたとき、あなたが自分のサービスを設計して作りはじめられる状態になっていることです。そのため最後の2章はハンズオンにしました。読書ログサービスという小さな題材を、本書の判断基準を使って設計し、最小構成で実装して育てていきます。

## 対象読者

- Go の基本文法を理解していて、次は設計を学びたい方
- クリーンアーキテクチャや DDD の本を読んだものの、自分のコードにどう落とすか迷っている方
- レイヤー分割や interface の置き場所について、チームで根拠を持って説明したい方

逆に、GoF デザインパターンの網羅的な解説や、特定フレームワークの使い方はこの本には書いていません。

## 本書の構成

全体は5つのパートに分かれています。

| パート | 章 | 内容 |
| --- | --- | --- |
| 原則を理解する | 第2〜4章 | 依存性ルール、Go の interface による DIP、他のアーキテクチャスタイルとの比較 |
| 層の設計判断 | 第5〜8章 | UseCase 層の要否、Repository の抽象化レベル、エラー、バリデーション |
| ドメインを表現する | 第9〜13章 | 値オブジェクト、集約、ドメインイベント、腐敗防止層、モジュール構成 |
| 動かして守る | 第14〜17章 | DI とコンポジションルート、トランザクション、テスト、CI での強制 |
| 作ってみる | 第18〜19章 | 読書ログサービスの設計と実装のハンズオン |

前から順に読む想定で書いていますが、各章は独立して読めるようにも作ってあります。いま悩んでいるテーマの章から読み始めて構いません。ただし第2章と第3章だけは、他のすべての章の前提になるので先に読むことをおすすめします。

## 用語の統一

元記事では表記が揺れていた用語を、本書では次のように統一します。

| 本書での表記      | 意味                                                              |
| ----------------- | ----------------------------------------------------------------- |
| domain 層         | エンティティ、値オブジェクト、Repository interface を置く最内層   |
| UseCase 層        | アプリケーションロジックを置く層。ディレクトリ名は `usecase/`     |
| Interactor        | UseCase 層の実装 struct。`CreateOrderInteractor` のように命名する |
| interface 層      | HTTP ハンドラなど外部との境界。ディレクトリ名は `interface/`      |
| infrastructure 層 | DB 実装や外部 API 連携などの技術詳細                              |

層の名前としては「UseCase 層」、その実装 struct の名前としては「Interactor」を使います。クリーンアーキテクチャの原典では Use Cases 層の実装を Interactor と呼んでおり、本書もそれに合わせました。

## サンプルコードの前提

- Go 1.22以降を前提にしています
- コード例は本書のために書き下ろしたもので、説明に必要な部分以外は省略しています
- エラーハンドリングも、章の主題に関係しない箇所では簡略化しています

それでは、同心円の図の話から始めます。
