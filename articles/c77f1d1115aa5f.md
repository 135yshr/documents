## はじめに

今まで商用 VPN サービスを使っていましたが、使う頻度の割に月額費用が高く、速度や同時接続数の制限といった使い勝手にも不満がありました。それなら自分専用の VPN を建ててしまえばよいのですが、構築・堅牢化・クライアント配布と手順が多いうえ、建てたあとのメンテナンスにも手間がかかります。

そこで、ConoHa VPS 上に自分専用の VPN を数コマンドで構築できる Terraform テンプレート「orenovpn」を作りました。この記事では、orenovpn の特徴と使い方を紹介します。

<https://github.com/135yshr/orenovpn>

## orenovpn とは

orenovpn は、ConoHa VPS Ver.3.0（OpenStack 準拠 API）上に個人用 VPN を構築するための Terraform テンプレートです。VPN 方式は次の 2 つから選べます。

- **WireGuard**: 高速・シンプルなモダン VPN。専用アプリで接続します
- **IKEv2/IPsec**: iPhone / macOS の標準 VPN 機能で接続できるため、アプリのインストールが不要です

`make deploy` で VPS を作成し、`make setup` でファイアウォール設定・SSH の堅牢化・VPN 構成・初期クライアント作成までを自動化します。iPhone へは QR コードで構成プロファイルを配布できるので、スマホ側の作業は読み取りだけです。

### 自分で VPN を建てるメリット

商用 VPN サービスではなく自前の VPN を選ぶ理由は、次のとおりです。

- 月々の費用は ConoHa の最安プラン（512MB）の数百円だけで済みます
- クライアントは `make client` で台数の上限を気にせず追加できます
- VPN 事業者に通信を預けず、通信経路を自分で管理できます
- Terraform・cloud-init・WireGuard といったインフラ技術の学習素材になります
- 不要になったら `make destroy` で跡形もなく撤去できます

なお、自前 VPN でも通信は VPS 事業者（ConoHa）と接続先のサーバーを経由します。信頼先が VPN 事業者から VPS 事業者へ移るだけなので、機密情報のやり取りには引き続き HTTPS/TLS を使ってください。

## 特長

テンプレートは、とにかく手数が少なくなるように作っています。

- `make deploy`（VPS 作成）→ `make setup`（VPN 構成）の 2 ステップで完結します
- 設定は `terraform.tfvars` の 1 ファイルだけで、最小 4 項目で動きます
- `make client NAME=<名前>` で鍵・証明書の発行から QR/プロファイル配布までできます
- `make check` と GitHub Actions の CI で、変更が壊れていないかを自動検証します

## アーキテクチャ

構成はシンプルで、ConoHa VPS（Debian 13）1 台の上に VPN サーバーを建て、手元の端末からの全通信を VPN 経由でインターネットに出します。次の図は WireGuard 選択時の構成です。

```text
  あなたの端末                 ConoHa VPS (Debian 13)
 ┌───────────┐   WireGuard    ┌──────────────────────────┐
 │ WireGuard │◄══ UDP :51820 ═►│ wg0  10.66.66.1           │
 │  Client   │   (暗号化)      │  ├ ufw (最小許可)          │
 └───────────┘                 │  ├ fail2ban / 自動更新     │──► インターネット
                               │  └ NAT (MASQUERADE)       │    （全通信を VPN 経由）
                               └──────────────────────────┘
```

`vpn_protocol = "ikev2"` を選んだ場合は、WireGuard の代わりに strongSwan による IKEv2/IPsec（UDP 500/4500）を構成します。

各レイヤで使っている技術は次のとおりです。

| レイヤ           | 使用技術                                          |
| ---------------- | ------------------------------------------------- |
| プロビジョニング | Terraform（OpenStack Provider）                   |
| サーバー初期構成 | cloud-init + シェルスクリプト                     |
| VPN              | WireGuard（既定）または IKEv2/IPsec（strongSwan） |
| OS               | Debian 13（cloud-init 対応イメージ）              |

### 2 フェーズ構成にした理由

デプロイは「フェーズ 1: Terraform で VPS を最小構成で作成」「フェーズ 2: `make setup` で SSH 経由の VPN 構成」の 2 段階に分けています。当初は cloud-init にすべてを詰め込むつもりでした。しかし ConoHa の user_data には base64 変換後で 16KiB までという制限があり、構成スクリプトが入りきりませんでした。2 段階へ分けたことで制限を回避できただけでなく、構成が失敗しても画面のログをその場で確認して再実行できるようになりました。

## 使ってみる

### 必要なもの

- [Terraform](https://developer.hashicorp.com/terraform/downloads) >= 1.5
- ConoHa アカウントと VPS Ver.3.0 の利用開始
- ConoHa の API ユーザー（コントロールパネル → API メニューで作成）
- SSH 鍵ペア（`ssh-keygen -t ed25519`）

### クイックスタート

リポジトリを clone（または fork）して、次のコマンドを実行するだけです。

```bash
# 1. 設定ファイルを用意（プリセットから作るのが簡単・推奨）
make preset PRESET=balanced   # simple | balanced | hardened | ikev2 から選ぶ
$EDITOR terraform/terraform.tfvars   # 認証情報と SSH 公開鍵を記入（最小 4 項目）

# 2. デプロイ（フェーズ1: VPS 作成）
make init
make deploy

# 3. SSH 疎通を確認（初回ブート 1〜2 分）
make status

# 4. ソフト導入・VPN 構成（フェーズ2）
make setup

# 5. クライアントを追加
make client NAME=my-phone

# 6. クライアント設定を配布
make show NAME=my-phone            # WireGuard=QR / IKEv2=導入案内 を表示
```

設定プリセットは `simple`（お試し）・`balanced`（バランス型）・`hardened`（堅牢化重視）・`ikev2`（iPhone/macOS 標準 VPN 向け）の 4 種類を用意しています。まずプリセットで土台を作り、必要な項目だけ `terraform.tfvars` で調整する流れです。

### iPhone からの接続

iPhone で使う場合は IKEv2 プリセットが便利です。`make serve-profile NAME=my-phone` を実行すると、構成プロファイルの一時配信サーバーが立ち上がります。表示された QR コードを iPhone の Safari でスキャンするだけで VPN 設定が完了します。専用アプリは不要で、iOS 標準の VPN 機能がそのまま使えます。

配信には Let's Encrypt の証明書を使うため、取得に成功していれば iPhone 側で警告は出ません。取得に失敗した場合は自己署名の証明書にフォールバックするので、Safari で警告を手動で承認する必要があります。

## セキュリティへの配慮

VPN サーバーはインターネットに露出するため、既定値の時点で堅牢になるよう設計しました。

- SSH は鍵認証のみで、root ログインとパスワード認証は無効化しています
- ufw によるファイアウォールで、必要最小限のポートだけを開放します
- fail2ban で SSH へのブルートフォース攻撃を遮断します
- unattended-upgrades による自動セキュリティ更新を有効にしています
- SSH の接続元だけは既定で全開放（`0.0.0.0/0`）なので、`allowed_ssh_cidr` を自宅などの固定 IP に絞ることを強く推奨します

さらに、`make doctor` を実行するとサーバーにログインして構成を自己診断してくれるので、「繋がらないけど原因がわからない」ときの切り分けにも役立ちます。kill switch や DNS 漏洩対策といった追加の堅牢化は、リポジトリの `docs/SECURITY.md` にまとめています。

:::message alert

`terraform.tfvars` と `*.tfstate` にはシークレットが含まれます。`.gitignore` 済みですが、公開リポジトリへ push しないよう注意してください。

:::

## 運用コスト

ConoHa VPS の最安プラン（メモリ 512MB）で動作します。個人の VPN 用途であれば 512MB で十分で、月に数百円ほどで運用できます（プランと料金の詳細は [ConoHa の料金ページ](https://vps.conoha.jp/pricing/) を参照してください）。使わない期間は `make destroy` で撤去してしまえば、費用はかかりません。

orenovpn を使うと、ConoHa VPS 上に自分専用の VPN を `make deploy` → `make setup` の 2 ステップで構築できます。MIT ライセンスで公開しているので、商用 VPN の月額費用や使い勝手に不満がある人は、乗り換え先として試してみてください。
