## はじめに

以前、MarkdownをPDFに変換するCLIツール **md2pdf** を作りました。

https://github.com/135yshr/md2pdf

もともとは「Markdownで書いた技術ドキュメントを、そのままきれいなPDFとして渡したい」という目的で作ったツールです。Mermaidや日本語フォントにも対応し、設計書やレポートをMarkdownで管理しながらPDFとして納品できるようにしていました。

ところが実際に仕事で使おうとすると、別の要求が出てきます。

**Markdownは同じままで、PDFの見た目だけ変えたい。**

顧客へ提出するレポート、セキュリティ診断報告書、技術提案書、社内標準フォーマットなどでは、GitHub風の見た目だけでなく、自社や顧客のブランドに合わせたデザインが必要になることがあります。

そこでmd2pdfに **Custom CSS機能** を追加しました。

```sh
md2pdf -css brand.css report.md
```

これでMarkdown本文を変更せず、PDFのデザインだけを変更できます。

## Markdownにデザインを持ち込まない

今回一番やりたかったのは、内容と見た目の分離です。

Markdown側にはできるだけ「意味」だけを書きます。

```markdown
# Security Assessment Report

## Executive Summary

今回の調査では3件のHighリスク項目を確認しました。

## Findings

| Severity | Finding |
| --- | --- |
| High | SQL Injection |
| Medium | Missing CSP |
```

見た目のためだけにHTMLをMarkdownへ埋め込み始めると、Markdown自体が特定の出力形式に依存してしまいます。

理想は次の分離です。

```text
Content
   ↓
Markdown

Design
   ↓
CSS
```

そこで、デザインは外部CSSとして渡す形にしました。

## 基本的な使い方

例えば次のCSSを用意します。

```css
body {
  font-family: "Noto Sans CJK JP", sans-serif;
  font-size: 11pt;
  line-height: 1.7;
}

h1 {
  font-size: 28pt;
  border-bottom: 4px solid #333;
  padding-bottom: 8px;
}

h2 {
  margin-top: 2em;
  border-left: 5px solid #333;
  padding-left: 12px;
}

table {
  width: 100%;
}
```

あとは次のように実行します。

```sh
md2pdf -css report.css report.md
```

Markdown本文は一切変更せず、PDFだけデザインを変更できます。

## CSSは組み込みスタイルの後に適用する

md2pdfには元々GitHub風のCSSがあります。Custom CSSは、その組み込みCSSの後に適用します。

```text
built-in CSS
    ↓
custom CSS
```

つまりCSSのCascadeをそのまま利用しています。

組み込みCSSをすべてコピーして変更する必要はなく、変更したい部分だけ上書きできます。

## CSSを複数指定できるようにした

`-css` は複数回指定できます。

```sh
md2pdf \
  -css company.css \
  -css customer.css \
  report.md
```

適用順は次の通りです。

```text
Built-in CSS
      ↓
company.css
      ↓
customer.css
```

後から指定したCSSが優先されます。

これは実際の業務を考えると便利です。例えば、

```text
styles/
├── company.css
├── security-report.css
├── customer-a.css
└── customer-b.css
```

としておけば、

```sh
md2pdf \
  -css styles/company.css \
  -css styles/security-report.css \
  -css styles/customer-a.css \
  report.md
```

のように、

```text
会社共通
   +
文書種類
   +
顧客固有
```

というレイヤーでスタイルを管理できます。

## HTML出力も追加した

Custom CSSを実装してすぐ気付いた問題があります。

PDFでCSSを調整するのは面倒です。

```text
CSS変更
 ↓
PDF生成
 ↓
PDFを開く
 ↓
確認
 ↓
CSS変更
```

そこで同時にHTML出力も追加しました。

```sh
md2pdf -format html document.md
```

Custom CSSとも組み合わせられます。

```sh
md2pdf \
  -format html \
  -css report.css \
  report.md
```

生成したHTMLをブラウザで開けば、CSSを変更してリロードするだけで確認できます。

```text
CSS変更
 ↓
Browser Reload
 ↓
確認
```

完成したら、

```sh
md2pdf -css report.css report.md
```

でPDFを作ります。

## HTMLとPDFで同じCSSを使う

この仕組みで重要なのは、HTMLとPDFで同じCSSを使うことです。

md2pdfのPDF生成は概ね次のパイプラインです。

```text
Markdown
   ↓
goldmark
   ↓
HTML
   ↓
CSS
   ↓
Chromium
   ↓
PDF
```

HTML出力は、この途中で止めるだけです。

```text
Markdown
   ↓
goldmark
   ↓
HTML + CSS
   ↓
report.html
```

そのためHTMLで確認したスタイルを、そのままPDF生成にも利用できます。

## Chromiumを直接操作する

md2pdfの初期バージョンではPDF生成にPython + Playwrightを使っていました。

現在はGoからChromium DevTools Protocolを直接操作しています。

```text
Markdown
 ↓
HTML
 ↓
CSS
 ↓
Chromium
 ↓
Page.printToPDF
 ↓
PDF
```

つまりPDF生成と言っても、実際には「Webページを作ってChromiumで印刷する」という考え方です。そのためCSSとの相性が非常に良いです。

## MarkdownとCSSをGitで管理する

この形にすると、MarkdownだけでなくデザインもGitで管理できます。

```text
docs/
├── report.md
└── styles/
    ├── base.css
    ├── security.css
    └── customer-a.css
```

デザイン変更も普通のコードと同じようにdiffでレビューできます。

```diff
 h1 {
-  font-size: 24px;
+  font-size: 28px;
 }
```

バイナリのWordテンプレートやPDFテンプレートと違い、見た目の変更履歴もGitで追跡できます。

これはDocs as Codeとの相性がかなり良いと思っています。

## CIでPDFを生成する

MarkdownとCSSをGit管理しているので、CIにも載せやすくなります。

```yaml
- name: Build report
  run: |
    md2pdf \
      -css styles/company.css \
      -css styles/report.css \
      report.md
```

すると、

```text
Markdown
   +
CSS
   +
Git
   ↓
CI
   ↓
PDF Artifact
```

という構成になります。

文書作成も、少しソフトウェアのビルドに近づきます。

## AI時代のドキュメント生成とも相性がいい

最近はAI Coding AgentやLLMに、設計書、調査報告、ADR、セキュリティレポート、実装計画などを書かせる機会が増えています。

AIにWord文書やPDFそのものを作らせることもできますが、個人的には、

```text
AI
 ↓
Markdown
 ↓
Review
 ↓
Renderer
 ↓
PDF
```

という構成の方が扱いやすいと感じています。

MarkdownならGit diffでレビューできます。出力の見た目はCSS側で制御できます。

```text
AI = Content
CSS = Presentation
Git = Review / History
md2pdf = Renderer
```

AIに毎回「この色にして」「この余白にして」と指示する必要もありません。AIには内容を書かせて、デザインは決定論的なCSSに任せられます。

## `</style>` を含むCSSは拒否する

Custom CSSを追加すると、一つ注意点があります。

md2pdfではCSSをHTML内の `<style>` にインライン展開しています。そのため、CSSファイルに `</style` が含まれているとstyle要素を閉じてHTMLを挿入できてしまいます。

そこで現在は、`</style` を含むCSSをエラーにしています。

CSSとして通常必要になる文字列ではないため、曖昧にエスケープするよりも明示的に拒否する方針にしました。

単純な「CSSファイルを読み込む機能」でも、実装してみると意外と考えることがあります。

## DOCXとConsoleは別の仕組み

Custom CSSはPDFとHTMLに適用します。

DOCXはPandocのreference document、ConsoleはGlamourのstyleを使っているため、それぞれ別の仕組みです。

```text
                  ┌─ PDF ─── CSS
                  │
Markdown ─────────┼─ HTML ── CSS
                  │
                  ├─ DOCX ── reference.docx
                  │
                  └─ Console ─ Glamour Style
```

出力形式に無理やり共通のスタイル機構を押し込まず、それぞれに適した仕組みを使っています。

## md2pdfが目指しているもの

最初にmd2pdfを作ったときは、

```text
Markdown → PDF
```

だけを考えていました。

現在は、

```text
                   ┌─ Terminal
                   │
Markdown ──────────┼─ HTML
                   │
                   ├─ PDF
                   │
                   └─ DOCX
```

となっています。

さらに今回、

```text
Content
   ↓
Markdown

Presentation
   ↓
CSS / Style
```

も分離できるようになりました。

最近はmd2pdfを単なるPDFコンバーターというより、

> Markdownを原本として、用途に応じた成果物を作るCLI

として考えるようになっています。

名前は完全に `md2pdf` なのですが。

## まとめ

md2pdfにCustom CSS機能を追加しました。

```sh
md2pdf -css report.css report.md
```

CSSは複数指定できます。

```sh
md2pdf \
  -css company.css \
  -css customer.css \
  report.md
```

HTMLでプレビューもできます。

```sh
md2pdf \
  -format html \
  -css report.css \
  report.md
```

今回の機能によって、

```text
Markdown = 内容
CSS      = デザイン
Git      = バージョン管理
md2pdf   = レンダリング
```

という構成が取れるようになりました。

特にAIでMarkdownを生成する機会が増えている今、**内容の生成と成果物のデザインを分離する**ことには以前より意味があると思っています。

Markdownでドキュメントを管理しつつ、顧客向け・社内向けのPDFも同じソースから作りたい方は、よければ試してみてください。

https://github.com/135yshr/md2pdf

```sh
brew install 135yshr/tap/md2pdf
```
