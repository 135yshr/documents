## この本について

「クリーンアーキテクチャというアーキテクチャは存在しない」と言われることがあります。私もこの言葉に賛成です。同心円の図をそのまま写しても、動くサービスは出てきません。あの図が教えてくれるのは依存の向きという原則だけです。レイヤーをいくつ作るか、interfaceをどこに置くか、DBへの依存をどこまで剥がすか。そこは全部自分で判断するしかありません。

この本は、私がGoでサービスを設計・運用する中で積み重ねてきた、その「自分で判断するしかない部分」の判断基準をまとめたものです。元になっているのはZennに公開してきた設計に関する記事群です。ただし単に束ねたのではなく、原則から実践へ一本の流れになるよう構成を組み直しました。記事間で揺れていた用語の統一と、誤りの修正も行っています。

ゴールは1つです。読み終えたとき、あなたが自分のサービスを設計して作りはじめられる状態になっていることです。そのため最後の2章はハンズオンにしました。読書ログサービスという小さな題材を、本書の判断基準を使って設計し、最小構成で実装して育てていきます。

## 対象読者

- Goの基本文法を理解していて、次は設計を学びたい方
- クリーンアーキテクチャやDDDの本を読んだものの、自分のコードにどう落とすか迷っている方
- レイヤー分割やinterfaceの置き場所について、チームで根拠を持って説明したい方

逆に、GoFデザインパターンの網羅的な解説や、特定フレームワークの使い方はこの本には書いていません。

## 本書の構成

全体は5つのパートに分かれています。

| パート | 章 | 内容 |
| --- | --- | --- |
| 原則を理解する | 第2〜4章 | 依存性ルール、GoのinterfaceによるDIP、他のアーキテクチャスタイルとの比較 |
| 層の設計判断 | 第5〜8章 | UseCase層の要否、Repositoryの抽象化レベル、エラー、バリデーション |
| ドメインを表現する | 第9〜13章 | 値オブジェクト、集約、ドメインイベント、腐敗防止層、モジュール構成 |
| 動かして守る | 第14〜17章 | DIとコンポジションルート、トランザクション、テスト、CIでの強制 |
| 作ってみる | 第18〜19章 | 読書ログサービスの設計と実装のハンズオン |

前から順に読む想定で書いていますが、各章は独立して読めるようにも作ってあります。いま悩んでいるテーマの章から読み始めて構いません。ただし第2章と第3章だけは、他のすべての章の前提になるので先に読むことをおすすめします。

## 用語の統一

元記事では表記が揺れていた用語を、本書では次のように統一します。

| 本書での表記     | 意味                                                            |
| ---------------- | --------------------------------------------------------------- |
| domain層         | エンティティ、値オブジェクト、Repository interfaceを置く最内層  |
| UseCase層        | アプリケーションロジックを置く層。ディレクトリ名は `usecase/`   |
| Interactor       | UseCase層の実装struct。`CreateOrderInteractor` のように命名する |
| interface層      | HTTPハンドラなど外部との境界。ディレクトリ名は `interface/`     |
| infrastructure層 | DB実装や外部API連携などの技術詳細                               |

層の名前としては「UseCase層」、その実装structの名前としては「Interactor」を使います。クリーンアーキテクチャの原典ではUse Cases層の実装をInteractorと呼んでおり、本書もそれに合わせました。

## サンプルコードの前提

- Go 1.22以降を前提にしています
- コード例は本書のために書き下ろしたもので、説明に必要な部分以外は省略しています
- エラーハンドリングも、章の主題に関係しない箇所では簡略化しています

それでは、同心円の図の話から始めます。
